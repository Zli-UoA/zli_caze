# Caze

A real-time room app (Void + Vite+ + Durable Streams + TanStack DB + Cloudflare Workers). Zli members sign in with AuthZ and post comments; event guests join through room-scoped invite links; Zli officers (`zli-officers`) manage rooms and invites. A separate `/room/:roomId/view` page renders comments as scrolling danmaku on canvas.

## Getting Started

> Package manager: pnpm (via `packageManager`). Do not use npm. Node version is pinned via `.node-version` (Void 1.6 requires `^24.22.0 || >=26.12.0`; Vite+ 1.4 requires `^22.18.0 || ^24.11.0 || >=26.0.0`).

Install dependencies:

```bash
pnpm install
```

### Development

Start the development server with HMR:

```bash
pnpm run dev        # vp dev
```

Your application will be available at `http://localhost:5173`.

For a temporary tunnel, allow its host when starting the dev server:

```bash
VITE_DEV_ALLOWED_HOSTS=<tunnel-host> pnpm run dev
```

Authentication uses AuthZ OIDC. For local development, create `.env` with the AuthZ client values and `PUBLIC_ORIGIN`, or use the development-only `CAZE_DEV_AUTH=1` login at `/auth/dev?name=Dev&admin=1`. The dev route is excluded from production builds.

```ini
AUTHZ_ISSUER=https://account.zli.works/api/auth
AUTHZ_CLIENT_ID=...
AUTHZ_CLIENT_SECRET=...
PUBLIC_ORIGIN=http://localhost:5173
CAZE_ADMIN_GROUP=zli-officers
CAZE_DEV_AUTH=1
```

Apply local D1 migrations before using rooms:

```bash
pnpm exec void db migrate
```

## Checks

```bash
pnpm run typecheck   # tsc --noEmit
vp check              # Oxfmt + Oxlint (type-aware)
vp test               # Vitest (src, durable-objects, pages tests)
vp build              # Void production build
```

`.github/workflows/ci.yml` runs `vp check`, `vp test`, and `vp build` on every pull request.

## Deploy

Merging to `main` runs `.github/workflows/void-deploy.yml`:

```text
pnpm install --frozen-lockfile
pnpm exec void deploy --platform cloudflare
```

Add the repository secret `CLOUDFLARE_API_TOKEN` before the first deploy. If the token can access multiple accounts, also add `CLOUDFLARE_ACCOUNT_ID` and pass it to the workflow. Set `CLOUDFLARE_WORKERS_SUBDOMAIN` as a repository variable if `workers.dev` is enabled and the Worker Version has no preview URL. `CF_ACCESS_CLIENT_ID` / `CF_ACCESS_CLIENT_SECRET` are only needed when Cloudflare Access protects the readiness URL.

Before the first authenticated deploy, register the Caze OIDC client in AuthZ, add the initial admins to the `zli-officers` group, and set `AUTHZ_CLIENT_ID`, `AUTHZ_CLIENT_SECRET`, and `PUBLIC_ORIGIN` with `void secret put`. `BETTER_AUTH_SECRET` is generated by Void on deploy if it is missing.

This change adds D1, AuthZ, and Durable Stream authorization. Do a non-destructive trial before cutover:

1. Set `cloudflare.name` to a separate Worker such as `zli-caze-void` and deploy that first.
2. Verify the AuthZ callback, D1 migration, admin room/invite flow, guest join, and comment posting.
3. Only then switch the Worker name to `zli-caze` (or cut traffic over) and remove the old Worker.

Do not delete the old `zli-caze` Worker before the new one is verified. Keep the previous Cloudflare Worker version available for rollback; D1 migrations are additive, but old Durable Object streams are not migrated.

## Notes

- `@tanstack/db` / `@tanstack/react-db` are pinned to `0.15.2` / `0.5.12`; StreamDB requires `@tanstack/db >=0.6 <1.0`. Upgrade both together.
- `void prepare` generates `.void/` types. `.void/` and `.cloudflare/` are gitignored.
- Pages live in `pages/`, API routes in `routes/`, and Durable Objects in `durable-objects/`.
- Each room is one Durable Stream at `/streams/:roomId`. `routes/streams/[...path].ts` mounts the shared `createStreamsHandler()`, backed by `durable-objects/streams.ts` (`defineDurableObject`, binding `STREAMS`).
- Room metadata lives in D1 (`rooms`). Admins create rooms at `/admin/rooms/new`; the server creates the stream, and clients never create streams for arbitrary IDs.
- Stream access is authorized: `link` rooms allow anonymous reads; `members` rooms require a member or invited guest. Posting always requires AuthZ or a guest session. The route generates the comment id and stamps `user`, `authorId`, `authorType`, and `createdAt` server-side; malformed events are rejected with 400.
- Guests join via room-scoped invite links (`/join/:token`). Invites have an expiry, optional use limit, and can be revoked. Guest sessions are stored in D1 and scoped to one room.
- Zli members sign in through AuthZ. The admin group is `zli-officers` (`CAZE_ADMIN_GROUP`), delivered through the AuthZ `groups` scope.
- Clients use `createStreamDB` from `@durable-streams/state/db`; `preloadCommentsDB()` only preloads the stream and stays connected via SSE. The server creates the stream when an admin creates a room. Temporary Cloudflare quick tunnels may cancel the SSE stream; in that case new comments appear after a reload.
- Old `Room` Durable Object data is not migrated. Existing rooms and comments are discarded; old room URLs return 404. Creating a room with an ID that still has an old stream is rejected.
- Admin group changes apply on the next AuthZ login. To revoke an admin immediately, invalidate their AuthZ session or Caze sessions.
- Guest invite URLs are shown only once because only the token hash is stored. Reissue the invite if the URL is lost.
- Custom endpoints have no app-level rate limit or moderation in the initial implementation.
